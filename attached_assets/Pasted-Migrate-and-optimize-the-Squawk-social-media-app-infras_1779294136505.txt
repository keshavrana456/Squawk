Migrate and optimize the Squawk social media app infrastructure using modern scalable services instead of temporary/local Replit storage.

IMPORTANT:
Do NOT store uploaded images, videos, stories, reels, or user data locally inside Replit filesystem because files disappear after restart/redeploy.

Use the following production-ready stack:

TECH STACK:

* Frontend Hosting → Vercel
* Database → Supabase PostgreSQL
* Media Storage → Cloudinary
* Realtime Features → Socket.io
* Frontend → React + Vite
* Backend → Node.js + Express

DATABASE:
Use Supabase PostgreSQL database for storing:

* users
* profiles
* posts
* chirps
* reels
* stories metadata
* comments
* likes
* followers/following
* messages
* notifications
* bookmarks
* hashtags
* mentions

Create optimized database schema and relationships.

AUTH INTEGRATION:
The app is already using Clerk authentication.
Requirements:

* connect Clerk user IDs with Supabase database users
* automatically create user profile after signup/login
* sync profile updates properly
* protect authenticated routes
* use Clerk session/user data throughout app

MEDIA STORAGE:
Use Cloudinary for:

* images
* videos
* reels
* stories
* profile photos
* post uploads

Requirements:

* upload files directly to Cloudinary
* store permanent Cloudinary URLs inside Supabase database
* never store uploads locally
* add image/video compression
* add upload progress bar
* support JPG, PNG, WEBP, MP4

UPLOAD FLOW:
User uploads media
→ Backend uploads to Cloudinary
→ Cloudinary returns permanent URL
→ Save URL in Supabase
→ Feed loads media using saved Cloudinary URL
